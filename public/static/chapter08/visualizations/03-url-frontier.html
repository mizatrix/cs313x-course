URL Frontier: Politeness & Priority

The Mercator frontier uses front queues for crawl priority and back queues (one host each) for politeness — so you never hammer the same server twice in a row.

⚖️
Try This: Add several URLs for the same host, then press Step repeatedly. Notice the scheduler refuses to fetch that host again until its politeness delay has elapsed — it picks a different ready host instead.

Front Queues — by Priority

A new URL is routed to a front queue by its priority. A prioritizer biases selection toward higher-priority queues.

Back Queues — by Host (Politeness)

Each back queue holds URLs for exactly one host. A router maps host → back queue, keeping per-host requests serialized and spaced out.

Heap of Host Ready-Times

The scheduler keeps a min-heap keyed on each host's ready time. It pops the earliest-ready non-empty host, fetches one URL, then pushes that host back with ready-time = now + delay.

Why It Matters

Priority (front) and politeness (back) are separated so a high-priority page can't trick the crawler into overloading one server. Hitting a host too fast looks like a denial-of-service attack and can get the crawler blocked or banned.
